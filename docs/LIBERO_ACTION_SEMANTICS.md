## Evidence

Raw collection:

- `collect_demonstration.py` reads collected `states` and `action_infos`, then writes `states` and `actions`.
- The source comment says states were recorded after playing actions, and the code deletes the last state before asserting `len(states) == len(actions)`.
- `libero_100_collect_demonstrations.py` has the same pattern.

Processed dataset creation:

- `create_dataset.py` loads raw `states` and `actions`, resets the simulator to `states[0]`, and iterates over `actions`.
- For each `j`, it calls `obs, reward, done, info = env.step(action)`.
- It checks that stepping `actions[j]` leads to `states[j + 1]` for `j < num_actions - 1`.
- It appends camera/proprio observations from the returned `obs`, then writes those observations and `actions[valid_index]` into the processed HDF5.
- Therefore processed `obs[k]` is the observation returned after executing the retained source action at the corresponding raw action index.

Official training usage:

- `libero/lifelong/datasets.py` uses Robomimic `SequenceDataset` with `dataset_keys=["actions"]`, `load_next_obs=False`, `frame_stack`, and `seq_length`.
- `libero/lifelong/main.py` loads each task dataset through this wrapper.
- `BasePolicy.compute_loss` computes policy loss against `data["actions"]`.
- This shows official behavior cloning pairs same-index observation tensors and action tensors, but it does not prove that same-index action is a future action after the processed observation.

## Final Convention

Convention B: processed HDF5 `actions[t]` is best interpreted as the action already aligned with the transition into processed observation `obs[t]`, i.e. the action associated with the transition from the previous retained observation toward `obs[t]`.

For SNN-WAM causal policy windows, use this explicit convention:

- `image_t = images[t]`
- `optional_state_t = states_or_proprio[t]`
- `action_history = actions[t-history_len+1:t+1]`
- `target_actions = actions[t+1:t+1+action_horizon]`
- `target_future_images = images[t+1:t+1+future_horizon]`
- `target_future_latents = latents[t+1:t+1+future_horizon]` once implemented

This differs from a pre-action convention where `actions[t]` would be executed after observing `obs[t]`.

## Remaining Uncertainty

- The evidence is source-code and HDF5-structure evidence, not a fresh pixel-level replay generated by this repository.
- Official LIBERO behavior cloning code uses same-index `obs` and `actions`; SNN-WAM uses the causal transition interpretation above to avoid training a policy to predict an action that already produced `image_t`.
- Any training code must record this convention in its config and result artifacts.
